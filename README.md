# 口コミ返信メーカー(review-reply)

Googleマップの口コミを貼るだけで、お店の口調に合わせた返信文の案を 3 つ作るツールです。

> 現在は雛形です。返信文の生成はルールベースのダミー(モック)で、外部の AI API は呼んでいません。

## 概要

- 口コミ本文・星の数・投稿者名を入力すると、内容を簡易判定(好評/賛否あり/不満、話題、要注意ワード)し、返信案を 3 パターン表示
- 「丁寧 / 親しみやすい / カジュアル / 上品・高級感」のトーンと、長さ(短め/ふつう/長め)を選べる
- 店名・業種・署名を一度設定すれば、毎回の返信に反映
- 生成器は `ReplyGenerator` インターフェースで差し替え可能。本実装では Cloudflare Workers 経由で LLM を呼ぶ想定

## 想定ユーザー

- Googleビジネスプロフィールを運用している個人店・小規模店舗のオーナー、店長(飲食・カフェ・美容室・整体・小売など)
- 口コミ返信が大事なのは分かっているが、文面を考える時間がない/毎回同じ文面になってしまう人
- 複数店舗の口コミ対応を任されているスタッフ・運用代行業者

## MVP の機能

- [x] 口コミ入力(本文・星・投稿者名)とサンプル口コミ
- [x] 店舗設定(店名・業種・署名)の保存
- [x] トーン・長さの選択
- [x] 口コミの簡易判定(好評/賛否/不満、話題ごとの好評・不満、健康被害や返金など要注意ワードの警告)
- [x] 返信案 3 つの表示・編集・コピー
- [x] コピーした返信の履歴(最新 20 件、端末内保存)
- [x] 月ごとの生成回数上限(無料 10 回 / 有料モック 300 回)
- [ ] LLM による生成(Workers の `/api/reply`。プロンプト組み立ては `src/lib/prompt.ts` に実装済み)
- [ ] ログインとサーバー側での回数カウント、課金

## 技術構成

- Vite 6 + React 18 + TypeScript の静的サイト(Cloudflare Pages に `dist` を置く想定)
- 保存は localStorage(`StateStore` インターフェースで Supabase へ差し替え可能)
- 主なファイル
  - `src/lib/analyze.ts` … 口コミの簡易判定(話題・感情・要注意ワード)
  - `src/lib/mockGenerator.ts` … ルールベースのダミー生成器
  - `src/lib/generator.ts` … 生成器の差し替えポイント(`createGenerator`)と、本実装用の HTTP 生成器の骨格
  - `src/lib/prompt.ts` … LLM 用プロンプトの組み立て(店舗情報・トーン・禁止事項・判定結果)
  - `src/lib/usage.ts` … 月ごとの回数上限

## 収益化案

- **月額サブスク(回数上限つき)**: 無料 月 10 回 / ライト 月 980 円・100 回 / スタンダード 月 1,980 円・300 回 などの段階課金
- 複数店舗・代行業者向けプラン(店舗ごとの口調プリセット、チーム共有)
- 将来: Googleビジネスプロフィール API 連携で「新着口コミの通知 → 返信案 → ワンクリック投稿」まで行う上位プラン
- LLM の原価は 1 回あたり数円以下に収まる想定なので、回数上限で原価を管理する

## 次にやること

1. Cloudflare Workers に `/api/reply` を作り、`buildPrompt` で LLM を呼ぶ(API キーは Workers の Secret に置き、ブラウザに出さない)
2. LLM の出力を JSON で受け、形式が崩れた時の再試行とモックへのフォールバック
3. Supabase Auth でログイン、生成回数をサーバー側でカウント(今のブラウザ内カウントは改ざんできる)
4. 店舗ごとの「よく使う言い回し」「NG ワード」を登録してプロンプトに反映
5. 業種別の例文ページ(SEO 用)と Cloudflare Pages のデプロイ設定
6. 課金(Stripe 等)の検討。特定商取引法の表記・利用規約・プライバシーポリシーの用意
7. 将来: Googleビジネスプロフィール API 連携(審査が必要)

## 注意

- 生成された返信は必ず内容を確認してから投稿してください。特に健康被害・返金などの口コミは、事実確認のうえ個別に対応してください
- サンプル口コミは架空のものです
